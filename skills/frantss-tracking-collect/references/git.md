# Local Git collection

Use read-only Git commands for configured local sources. Verify the exact author email in `identity` and each canonical checkout root in `scope.repositories`. Paths refer to the machine that holds this configuration; Git sources require no configured `instance`.
Resolve each root's canonical `git rev-parse --git-common-dir` against the checkout directory. Linked worktrees share that repository scope. Deduplicate repositories by common directory; distinct clones remain separate. Paths moved since registration need configuration maintenance.
Enumerate configured repositories' local refs, their HEAD, and linked worktree HEADs from `git worktree list --porcelain`; include detached worktree commits. Record the selected tip hashes for resumable scans. Inspect only commits reachable from those tips; do not fetch, change refs, or scan reflogs.
Read full commit hashes, raw author email, author timestamp, committer metadata, parents, and subject. Match the configured email exactly against the raw author email (`%ae`), without mailmap rewriting or author-name/substring matching. Use author time (`%aI`) for the authored event, converted to the requested local calendar window. Keep committer details as context; a matching committer alone does not establish authorship.
Git's usual `--since`/`--until` filters select by committer time, so they cannot establish completeness for an author-time window. Traverse reachable history within the call/item budget and filter author times explicitly. Reaching a budget or missing object leaves coverage partial; retain traversal position and selected tips. Do not advance checkpoints from the newest commit or assume history is ordered by author time.
Emit one authored-commit event per matching commit, including merges. Use the full commit hash as `object_id`, `authored` as `event_id`, `authored-commit` as `action`, raw author email as `actor`, the canonical common directory as evidence `instance`, and null as `source_scope` because commit IDs are unique within that repository. This keeps repeated refs/worktrees from duplicating a commit. Retain the hash, subject, timestamps, attribution, and repository location in context. Keep `source_url` null unless an actual verified object URL is available.
Report the repository scopes, selected tips, traversed/matched counts, traversal cursor, and requested author-time window. Shallow repositories and missing objects leave history gaps; commits outside selected refs/HEADs are outside coverage. A checkpoint is complete only after the reachable history is exhausted and evidence writes verify. Incremental runs must still cover newly reachable commits with older author dates. Uncommitted files, deleted history, GitHub events, and activity on other devices are outside commit collection. An authored commit is contribution evidence; it does not establish completion of a task.
