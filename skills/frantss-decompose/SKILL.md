# Decompose

Help frantss understand a problem, choose an approach, and break it into manageable parts.
Apply to problems of any kind. Execute the resulting plan only when explicitly requested.

## Start and resume

Before creating or updating the live Markdown file, read [record rules](references/records.md).
Maintain that file from the first exchange. On resume, read it and continue from its recorded stage and agreements.

## Stage guides

Read only the guide for the current stage. Load the next guide when the current stage's completion criterion is met.

1. For context, purpose, and problem framing, read [framing](references/framing.md).
2. Once the framing is accepted, read [approaches](references/approaches.md) to assess alternatives and agree on a direction.
3. Once the direction is agreed, read [first-level structure](references/structure.md).
4. Once the first level is agreed, read [developing a part](references/part.md). Repeat this stage one major part at a time.
5. Once every major part is accepted, perform the completion review below.

## Conversation rules

Keep each round within the current stage or part, at the level under discussion.
The frontier is the unanswered questions that can be asked without assuming answers to other open questions.
Ask the whole frontier together; dependent questions belong in a later round.
Investigate available facts through permitted sources; ask frantss for missing facts you cannot obtain and choices they must make.

Give each question its stable ID and a clear title.
For decision questions, give a recommended answer, reasoning, and main tradeoff; word the question so "yes" accepts the recommendation.
For factual questions, leave unknown facts visibly unanswered.

Wait for answers before advancing. Apply answers only to the points frantss addressed; keep unanswered questions open and recommendations proposed.
Recompute the frontier after each round. Reuse existing answers instead of asking for repeated confirmation.
Capture details raised early as deferred notes under their relevant part, then return to the current discussion.

When evidence changes a parent decision, explain the effect and return to its stage guide to review the affected structure.
Pause only dependent work; retain unaffected agreements and unanswered questions. Apply the record rules for replacements.

## Completion

Review whether the parts cover the agreed goal, fit together, and support the intended next step.
Reconcile cross-part decisions and dependencies. Resolve, assign a follow-up to, or explicitly exclude each deferred note.
Resolve blocking questions with frantss; retain nonblocking unknowns with their implications and follow-ups.
Present the complete Markdown document for final review, with remaining uncertainty visible.
Complete the discussion when frantss accepts the whole document and every recorded blocking question is resolved.
